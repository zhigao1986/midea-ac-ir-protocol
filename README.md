# 美的空调红外协议（Midea AC IR Protocol）

逆向自 18 组实测抓包（制冷 / 制热，16.0–24.5℃），**已完整解出温度字段**，
包括多数资料缺失的 **16℃** 和 **0.5℃ 半度**。

> 本仓库只包含协议资料、抓包样本和分析脚本，不含任何固件/Arduino 代码。

## 快速事实

| 项目 | 值 |
|---|---|
| 载波 | 38 kHz |
| 引导头 | mark 4400 µs + space 4400 µs（实测 4406–4428） |
| 位 mark | 536–542 µs |
| bit 0 | space 536–542 µs |
| bit 1 | space 1614–1620 µs |
| 帧尾 | mark 560 µs + space 5222 µs |
| 位序 | MSB first |
| 一次按键 | **3 帧**：`F0 + F0 + F2`（F0 重复一次，F2 是状态帧） |
| 帧间隔 | 约 5.2–5.6 ms |

## 帧格式

### F0（命令帧）

```
B2 4D BF 40 [X] [CHK]
```

| 字节 | 含义 |
|---|---|
| 0–3 | `B2 4D BF 40` 固定 |
| 4 | 高 4 位 = `Gray(温度-17)`；低 4 位 = 模式（制冷 `0x0`，制热 `0xC`） |
| 5 | `~XOR(b0..b4)`（异或取反） |

### F2（状态帧）

```
D5 66 [A] [B] 00 [CHK]
```

| 字节 | 含义 |
|---|---|
| 0–1 | `D5 66` 固定 |
| 2 | bit5 `0x20` = **半度（.5℃）** |
| 3 | bit4 `0x10` = **16℃ 标志** |
| 4 | 样本恒为 `00` |
| 5 | `sum(b0..b4) & 0xFF` |

> F0 和 F2 使用**不同**的校验规则，别混用。

## 温度编码（关键）

```text
n    = clamp(温度 - 17, 0, 13)     // 16 / 16.5 也取 0
gray = n ^ (n >> 1)                // 4 位格雷码
F0[4] = (gray << 4) | (制热 ? 0x0C : 0x00)
F2[2] |= 0x20                      // 温度带 .5
F2[3] |= 0x10                      // 温度 == 16
```

### 格雷码表

| 温度 | n | Gray | F0[4] 制冷 | F0[4] 制热 |
|---|---|---|---|---|
| 16.0 / 16.5 | 0 | 0 | `00` | `0C` |
| 17.0 / 17.5 | 0 | 0 | `00` | `0C` |
| 18.0 / 18.5 | 1 | 1 | `10` | `1C` |
| 19.0 | 2 | 3 | `30` | `3C` |
| 20.0 | 3 | 2 | `20` | `2C` |
| 21.0 | 4 | 6 | `60` | `6C` |
| 22.0 | 5 | 7 | `70` | `7C` |
| 23.0 | 6 | 5 | `50` | `5C` |
| 24.0 / 24.5 | 7 | 4 | `40` | `4C` |
| 25.0 | 8 | 12 | `C0` | `CC` * |
| 26.0 | 9 | 13 | `D0` | `DC` * |
| 27.0 | 10 | 15 | `F0` | `FC` * |

## 生成示例（Python）

```python
def build(t10, heat=False):
    """t10 = 温度 × 10，例如 165 表示 16.5℃"""
    whole, frac = divmod(t10, 10)
    n = max(0, whole - 17)
    gray = (n ^ (n >> 1)) & 0x0F

    f0 = [0xB2, 0x4D, 0xBF, 0x40,
          (gray << 4) | (0x0C if heat else 0x00), 0]
    f0[5] = ~(f0[0] ^ f0[1] ^ f0[2] ^ f0[3] ^ f0[4]) & 0xFF

    f2 = [0xD5, 0x66, 0x00, 0x00, 0x00, 0x00]
    if frac == 5:
        f2[2] |= 0x20
    if whole == 16:
        f2[3] |= 0x10
    f2[5] = sum(f2[:5]) & 0xFF

    return bytes(f0), bytes(f2)
```

按 `F0, F0, F2` 顺序发送，帧间约 5.6 ms。

## 为什么 16℃ / 半度容易被漏掉

- 16℃ 与 17℃ 的 **F0 完全相同**，区别只在 F2 的 `0x10`；
- 0.5℃ 只在 F2 的 `0x20`；
- 如果只抓/只发前两帧（F0+F0），就会丢掉 F2，空调永远显示 17℃。

## 抓包格式

`captures/*.json` 为原始波形：

```json
{"tick_us": 2, "len": 299, "us": [4406, 4428, 536, 1620, ...]}
```

- `us` 交替为 **mark / space**，单位微秒，从第一个 mark 开始；
- `tick_us` 是采样精度（本仓库样本为 2 µs）。

任何 38 kHz 接收头 + 逻辑分析仪 / 单片机采样都能产出同样格式。

## 适用性说明

- 这是 **某一台美的空调 + 原装遥控器** 的实测结果，机型/批次不同可能有差异；
- 美的还有 `A1/A4` 开头的 48bit 通用帧（数据帧 + 反码帧），与本协议不是同一种；
- 风扇、摆风、睡眠、ECO、电辅热等字段尚未定位（样本均为风速自动）；
- 欢迎提交更多机型/功能的抓包（格式同上），一起补全。
